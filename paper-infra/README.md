# ResearchVault Paper Resolution Infrastructure — Stage 1

This directory contains **infrastructure-only scaffolding** for the future paper-resolution architecture.

## Production safety boundary

Stage 1 deliberately does **not** modify or route production traffic from:

- `researchvault-bot`
- `researchvault-marketing`
- `rv-shadow`
- `researchvault-proxy`
- existing D1/KV/payment/Telegram logic

The existing Telegram bot remains the production source of truth until a later, explicitly approved migration/cutover.

All Stage 1 Workers are **internal-only** Cloudflare services: `workers_dev=false`, `preview_urls=false`, and no public route/custom domain is configured. They are intended to communicate only through Service Bindings.

## Planned topology

```text
researchvault-bot  (NOT CONNECTED IN STAGE 1)
        |
        v
rv-doi-resolver
        |
        v
rv-pdf-finder
   |    |    |    |    |    |    |
   v    v    v    v    v    v    v
 src01 src02 src03 src04 src05 src06 src07
```

Source-worker groups:

1. `rv-source-01-oa` — open-access discovery
2. `rv-source-02-biomed` — biomedical repositories/indexes
3. `rv-source-03-preprints` — preprints and institutional repositories
4. `rv-source-04-publishers-a` — major publisher family A
5. `rv-source-05-publishers-b` — major publisher family B
6. `rv-source-06-society-tech` — society/engineering/physical-science sources
7. `rv-source-07-longtail` — long-tail/fallback discovery

## Current behavior

Every Worker exposes `/health` to upstream Service Bindings. Resolver/finder/source endpoints that would perform real resolution intentionally return HTTP `501` with `infrastructure_only`. No publisher traffic is generated by this scaffold.

All logs are structured JSON and are intended for Cloudflare Observability only. They are never returned in Telegram user messages.

## Stage 1 verification

Stage 1 was deployed and smoke-tested end to end on Cloudflare before the temporary smoke gateway was removed.

Verified path:

```text
rv-doi-resolver -> rv-pdf-finder -> all seven source Workers
```

The end-to-end smoke response returned `HTTP 200` with `ok: true`; all seven source bindings returned `HTTP 200`. The production Telegram bot remained disconnected throughout the test.

## Mandatory QA before deployment

After installing dependencies, run the safety and bundle checks before any deployment:

```bash
cd paper-infra
npm install
npm run check
```

`npm run check` validates the isolation rules, binding topology, Stage 1 blockers, JSON contracts, and performs Wrangler dry-run bundles for all nine Workers. A failed check means **do not deploy**.

## Deployment order

Because Service Bindings require the target service to exist, deploy in this order only after QA passes:

```bash
npm run deploy:sources
npm run deploy:pdf
npm run deploy:doi
```

`npm run deploy:all` executes the same order.

## Important

Do **not** add bindings from `researchvault-bot` to these Workers yet. That belongs to a later migration stage after the current bot architecture has been audited and a regression baseline has been established.
